# 做了什么

修复 APP 投递读取城市配置时，历史 UTF-8 乱码无法匹配城市选项导致任务失败的问题。

# 改了哪些

- `LiepinService` 统一解析城市名称、城市码和 UTF-8 乱码，并只接受数据库中的规范选项。
- `ConfigService` 和配置保存入口复用同一解析链路，保存结果统一为规范城市名。
- 未知城市配置返回 HTTP 400 和明确错误信息。
- 新增服务、配置读取和控制器回归测试。

# 怎么验证

- 定向 Java 测试通过。
- Java 全量测试通过。
- 前端 lint 和生产构建通过。
- 新后端重载后，城市码 `410` 保存并回读为 `全国`。
- 未知值 `BAD_CITY` 返回 HTTP 400。
- 隔离回滚恢复基线哈希并清理新增测试文件。
- 真实投递启动受当前登录态门槛拦截，任务保持空闲。

# 对 `codestable/` 的影响

新增 `.codestable/features/2026-08-08-city-code-normalization/`，包含基线哈希、补丁、验证记录和回滚脚本；项目规格保持原样。
